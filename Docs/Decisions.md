# Decision Log

One row per decision. Newest at the bottom. Design decisions also get their tag updated in `GDD.md`.

## Decided

| Date | Area | Decision | Why / alternatives |
|---|---|---|---|
| 2026-10-28 | Rendering | **HDRP** (Unity 6000.3.24f1) | Volumetric fog and lighting are the look. The project was recreated from URP |
| 2026-10-28 | DI | **VContainer** 1.19.0 | Fast, maintained, simpler than Zenject. Zenject/Extenject isn't developed any more. Plain singletons (as in Bouncer) don't scale |
| 2026-10-28 | Async | **UniTask** 2.5.11 | Zero-alloc, works with VContainer (`IAsyncStartable`) and Addressables |
| 2026-10-28 | Netcode | **NGO 2.13.3 + Multiplayer Services sessions over Relay** | Already known from Bouncer. The host is the server. Steam later behind `ISessionService` |
| 2026-10-28 | Voice | **Vivox** behind the Voice assembly | Already installed, positional channels, participant audio taps for DSP. Can be swapped without touching Gameplay |
| 2026-10-28 | Assets | **Addressables** through scoped `IAssetProvider` | Releases a scope's loads with that scope, which suits modular levels and entities |
| 2026-10-28 | Data | Configs are ScriptableObjects registered as instances in scopes | No string addresses for configs, injected where they're needed |
| 2026-10-28 | Code layout | Layered assemblies `App → UI → Gameplay → (Voice, Networking) → Infrastructure → Core`, one installer per assembly | Enforced boundaries without asmdef-per-folder sprawl |
| 2026-10-28 | Events | Own minimal `IEventBus` in Core | No extra package. Only for notifications across modules |
| 2026-10-28 | Flow | A `StateMachine` per scope (root: `GameStateMachine`) | No resolving states across containers (the Symbols "local container" hack) |
| 2026-10-28 | Repo | Repository `github.com/begod24/maze`, root = the Unity project folder. Blender sources in `ArtSource/`. "maze" is only the repo name, and the game title stays No Way Out | Same layout as Symbols and Bouncer. The user commits and pushes |
| 2026-10-28 | Repo | Git LFS for binary assets, LF line endings, `.gitkeep` in empty folders. Only the concept boards are kept as references (`Docs/References/ConceptArt`) | Unity uses Force Text, so YAML stays diffable. The PDF and Symbols docs are already reflected in our Docs |
| 2026-10-28 | Docs | Technical docs, rules and skills in English, GDD in Russian | Matches code identifiers. The GDD is the designer's own document |
| 2026-10-28 | Packages | Removed Post Processing v2 and Visual Scripting. Added AI Navigation and Multiplayer Play Mode | PPv2 doesn't apply to HDRP. Runtime NavMesh and in-editor multiplayer testing are needed |
| 2026-10-28 | UI | **UI Toolkit**: UXML/USS, View + Presenter, `IScreenService` | Modern UI with data binding and Localization bindings. uGUI was the alternative |
| 2026-10-28 | Animation | **USS transitions for UI, PrimeTween 1.4.11 for the world** | PrimeTween is free, zero-alloc and installs through UPM (npm registry). DOTween would allocate and needs an Asset Store import |

| 2026-10-28 | Animation | **Mixamo + Blender**: locomotion from Mixamo on a Humanoid rig, unique actions (entities, "help up") in Blender | Fast start, retargetable through Humanoid |
| 2026-10-28 | Music | **Dark ambient with stem layers**, melody only in the menu and finale, no vocals. Moments: menu/lobby, run ambience, entity stingers, exit/finale | Voices are gameplay, so music must never sound like speech |
| 2026-10-28 | Tooling | The dev machine is **Windows 11**. Docs and skills use Windows paths (Git Bash for shell commands, Blender 5.2.3 from Steam, Editor.log in `%LOCALAPPDATA%`) | The project moved from macOS. The macOS paths no longer worked |
| 2026-10-28 | Repo | The second concept document is kept as `Docs/References/GDD_v2_Concept.pdf` (LFS). Its two new points went to GDD §16 | The user wants the source next to the GDD. This supersedes "only the concept boards are kept" |
| 2026-10-28 | Repo | `OutdoorsScene.unity` moved to `Scenes/Sandbox/` as a lighting reference | As planned in TechnicalOverview §4 |
| 2026-10-28 | Networking | **Dev quick start over Relay**: in the editor, every Multiplayer Play Mode player calls `CreateOrJoinAsync` with a per-machine dev session ID and goes straight to Gameplay. The main editor joins first and usually hosts | Tests the real Relay path without a menu. Alternative was a local 127.0.0.1 connection. Risk: a stale session after an abrupt stop |
| 2026-10-28 | Player | **CharacterController**, owner-authoritative `NetworkTransform` (position + yaw), Cinemachine camera active only for the owner | Predictable stairs and little tuning. Rigidbody was the alternative (natural pushing, but jitter on stairs and harder networking) |
| 2026-10-28 | Player | Falling into the void respawns the player at its spawn point [TEMPORARY] | Placeholder until death and the Echo are designed (GDD §4.4–4.5) |
| 2026-10-28 | Input | Generated `GameInputActions` wrapped by `IInputService` with modes (Gameplay, UI, Disabled). The Player map is keyboard and mouse only | Typed access, no `PlayerInput`. Gamepad stays open (GDD §1) |
| 2026-10-28 | Networking | Network prefab handlers register when the scene scope is built (`IInitializable`), and players spawn on `OnLoadComplete` / `OnSynchronizeComplete` | With `IStartable`, the host or a late joiner could spawn objects before the handlers existed, and those copies would miss injection |
| 2026-10-29 | Networking | Online stays **Relay + Multiplayer Services** (sessions, join by code), as in Bouncer. Steam comes later behind `ISessionService`. The dev quick start is **off by default** | The menu with join by code is the real path. Quick start is a checkbox for fast gameplay tests |
| 2026-10-29 | Networking | Only Gameplay is a network scene (`VerifySceneBeforeLoading`). Session state reaches App and UI through bus events | A client joining a host in the menu must keep its own menu and lobby instead of reloading the host's scene |
| 2026-10-29 | UI | **Main menu = variant 4 "TV signal"**: a 3D HDRP room with 5 CRT TVs (Create, Join, Settings, Credits, Quit), screen stills under a CRT shader, distortion on hover, camera push-in as the full-screen transition. Simple lobby (code, players, Start, Leave). Settings and Credits are "coming soon" | The user picked variant 4 from the menu board. Flat UI Toolkit TVs and live camera feeds were the alternatives |
| 2026-10-29 | UI | UI foundation: `GamePanelSettings`, `GameTheme.tss`, `Variables.uss`/`Common.uss`, Scoped `IScreenService` + `UIScreensConfig`, fonts **Oswald + IBM Plex Mono** (OFL, Cyrillic). | 2026-10-29 | Art | First third-party prop: **Poly Haven Television 01** (CC0), re-exported through Blender (`Scripts/Props/import_television01.py`). FBX export uses **Y forward, Z up** with Unity's Bake Axis Conversion | `-Z forward / Y up` without Apply Transform left a 90° rotation on the root node in Unity |
| 2026-10-29 | World | **Procedural floors now**, on a **3D grid of 4 m cells** [PROPOSED size]. Templates: linear 4-phase first, then Escher tower and hub. Both start variants (two paths / real + loop) are generator options. A floor takes 8–10 minutes for two | The user wants a procedural world. A grid avoids overlaps, makes vertical layouts easy and makes void reshaping a module swap. Socket chains and hand-made chunks were the alternatives |
| 2026-10-29 | Art | The level blockout is built from **Blender module scripts** (not ProBuilder or Unity cubes) and replaces `GreyboxSandbox` | The same modules serve the generator |
| 2026-10-29 | Rendering | First look pass: triplanar concrete and puddles, the void look (fog, light shafts, dust, floating blocks), the perception distortion. Concrete from **Poly Haven CC0**. Glitch faces later | The user's pick |
| 2026-10-29 | Art | **Modular kits live in one folder** (`Art/Environment/Modules`, `Prefabs/World/Modules`, `Data/World/Modules`), not one folder per piece | The user's rule for modular models |
| 2026-10-29 | Art | Blender objects named `COL_*` become **BoxColliders** on import (renderer removed). Empties `Spawn_N`, `Illusion_N`, `Door_*` mark points. One build script per kit, one `.blend` per module | Simple primitive colliders without hand work. Separate `.blend` files keep object names free of `.001` suffixes |
| 2026-10-29 | World | The floor seed travels through an in-scene `FloorState` (`NetworkVariable<int>`), and every peer builds the floor locally | The geometry is never sent. The server builds before players spawn |

| 2026-10-29 | Rendering | The CRT effect is a **CustomRenderTexture shader** (`NoWayOut/CRT Screen`) shown through an HDRP Unlit emissive material with exposure weight 0 | Pipeline-agnostic and simple to tune, no hand-written Shader Graph JSON. Screen brightness doesn't depend on scene exposure |
| 2026-10-29 | Tooling | A **second dev machine on macOS** works in parallel with the Windows one. Its paths and rules live in a gitignored `CLAUDE.local.md`, and the shared docs and skills keep the Windows paths | Shared files don't get per-machine edits, so the two machines don't conflict over them. Listing both platforms in the shared docs was the alternative |
| 2026-10-29 | Rendering | **Realistic HDRP look** replaces the stylized direction (GDD §10). `VP_Gameplay`: dark "Otherworld" fog (mean free path ~18 m [PROPOSED], base at the lowest level), gradient sky, fixed exposure EV 0, cold light from above with volumetric shafts, warm `WarmLamp`s at doorways, start and exit, ACES, film grain, vignette, SSAO | The user's pick: Silent Hill fog, the dark option, slightly more readable. A light grey SH2 fog was the alternative, but its flat light weakens the "no shadow" tell |
| 2026-10-29 | Rendering | **Moving fog**: a seeded floor-wide Local Volumetric Fog with scrolling 3D noise (`VoidFogDrift`, constant patch size) plus a denser mist below the floor (`VoidMist`) | The user wants the fog to move. Global HDRP fog has no noise of its own |
| 2026-10-29 | Art | Concrete is **Poly Haven CC0 PBR, triplanar** (`concrete_floor_worn_001`, `concrete_wall_006`, `concrete_layers_02`, 2k), ARM packed into HDRP masks. **SSR** on (High Fidelity, Balanced), **SSGI** on (High Fidelity). **Puddles** are seeded HDRP decals with flat normals and high smoothness | Realism, and the puddle tell (GDD §3.4) needs reflections. Module detailing (bevels, chips) was postponed |
| 2026-10-29 | VFX | Particles use the **built-in Particle System** with our HDRP shader `NoWayOut/Void Particle` (vertex color, soft particles, HDRP fog, exposure). Dust and rising smoke follow the camera through `WorldAlignedFollower`. VFX Graph stays for heavy effects later | Claude can build Particle Systems from code. VFX Graph graphs need hand authoring. VFX Graph itself has no macOS/Windows conflict |
| 2026-10-29 | World | **Winding linear template.** Each lane wanders inside its own half of the floor (upper = east, lower = west), only north or sideways, with turns, stairs (levels ±5), doorways and forks. A fork's side branch ends in a dead end, sometimes behind a door to nowhere. Lanes merge by level, column and row before the junction. Upper lane 140–160 steps, lower 90–110 (main route ~180 modules, ~4 min of pure walking) | The old floor was a straight 96 m strip that took 1–2 minutes. Separate halves keep the lanes from colliding, so attempts rarely fail. ~450 modules for 8–10 pure minutes was rejected (performance, repetition) |
| 2026-10-29 | World | `ModuleFork` and `ModuleDeadEnd` definitions reuse the Platform prefab, as `ModuleTurn` does | No new Blender modules needed |
| 2026-10-29 | World | The floor's atmosphere (drift fog, mist, floating blocks, puddles) is client-local, built by `FloorAtmosphere` from the floor seed, so every player sees the same void | Like the modules, it never goes over the network |
| 2026-10-29 | Rendering | **Dense fog, 8–10 m visibility** (the user's number). Global height fog: mean free path 4 m, base above the top level (+24 m), so density is the same on every level. Fog is lit by a brighter gradient-sky ambient (sky exposure 3.6) because HDRP's height fog also attenuates the directional light (`TransmittanceHeightFog`), so the sun can't light dense fog. `VoidFogDrift` is a light moving layer (mfp 12, patchy mask) | An 18 m fog wasn't dense enough. Dense fog made of local volumes was the alternative, but it can't be checked in editor previews |
| 2026-10-29 | Rendering | **Weather changes during a floor.** The server runs a seeded-random schedule of presets (Calm, Drizzle, Downpour, Thunderstorm, Ash Fall, Gale) in `WeatherState` (`NetworkVariable<int>`). Every client blends to it over 25 s (`WeatherService`), and `WeatherView` draws rain (splashes, ripples), lightning, ash, wind and fog changes. Visual only for now | The user's pick. One weather per floor and weather-as-illusion were the alternatives (the latter is in the GDD for later) |
| 2026-10-29 | Rendering | **Living puddles and wet surfaces.** A 16-shape puddle decal atlas, a `PuddleField` registry, wetness that rises in ~40 s of rain and dries in ~120 s, puddles that grow and fade with it, ripples emitted only inside nearby puddles, and a camera-anchored wet-surface decal | The user wants realistic, dynamic puddles and rain on the ground. Animated decal shaders would need Shader Graph |
| 2026-10-29 | Workflow | **Everything visual is realistic** (CLAUDE.md rule) | The user's standing rule: HDRP was chosen for realism (now URP, the rule stays) |
| 2026-10-29 | Workflow | Claude may **open, switch, edit and save scenes** and reports every scene action. It never discards changes that were unsaved before it started | The user's standing permission. Before, Claude could only work additively and never touch the open scene |
| 2026-10-29 | Rendering | **Thinner, more volumetric fog** (replaces the 8–10 m row above). Global height fog mfp 4 → 10 m. Density variation comes from two scrolling noise layers: `VoidFogDrift` banks (mfp 8, 20 m patches, ~0.45 m/s) and new `VoidFogWisps` (mfp 20, 7 m patches, ~0.7 m/s, slowly rising). Average mfp ~6 m (was ~3.5): silhouettes at ~15–18 m, 25–30 m in clear gaps, 8–10 m inside a bank. Weather: dense mfp 3.2 → 5, gust-clear 7 → 20 | The user played it: the fog felt too dense and flat. Uniform dense fog hides its own structure, so the patchy layers now carry part of the density |
| 2026-10-29 | Rendering | **Living, realistic fog at the GDD's 8–10 m** (replaces the "thinner fog" row above). Global mfp 7, `VoidFogDrift` mfp 4, `VoidFogWisps` mfp 16: average ~3.8 m, 4–5 m inside a bank, 15–20 m in a gap. Fog layers "breathe" (density ±30–45% over 17–50 s, Perlin) and drift with the weather wind (`FogField` + `WeatherView`). Albedo raised to a realistic water-droplet value (×1.8), fog GI dimmer 0.55 keeps the ambient glow as before, so lamps and lightning light the fog ~1.8× more | The user: an otherworldly limbo with Silent Hill fog, confusing navigation, fog that feels alive, 8–10 m as in the GDD. A bright foggy day like the reference video, a lighter fog in a dark world, and a separate "foggy morning" weather were the alternatives |
| 2026-10-29 | Rendering | **URP replaces HDRP** (the user's call; realism stays the rule). URP 17.3, Forward+, three quality tiers (`URP_HighFidelity`, `URP_Balanced`, `URP_Performant`) with Decal (DBuffer, albedo + normal + MAOS), SSAO and Volumetric Fog features. HDRP, its `Assets/Settings` assets, `HDRPProjectSettings` and the HDRP template scene `Sandbox/OutdoorsScene` are removed. Lost from HDRP: SSR, SSGI, physical light units and exposure | The user's pick, with the fog rebuilt as our own raymarcher in the same task. A built-in-fog-plus-particles look and a paid fog asset were the alternatives |
| 2026-10-29 | Rendering | **Own volumetric fog** in the new `NoWayOut.Rendering` assembly: `VolumetricFog` volume override (height fog, scattering), `LocalFogVolume` boxes with 3D noise (registered in a `FogVolumeSet` asset instead of static state), `VolumetricFogFeature` (Render Graph: half-res raymarch with main light shadows and Forward+ lights, depth-aware blur and upsample). Like HDRP, the sun is attenuated by the height fog above each point (fog and `NoWayOut/Triplanar Lit`); lightning isn't | Matches the HDRP look (checked against HDRP captures of the same views). A froxel/compute version was the alternative; the fragment raymarch can use URP's shadow and cluster light code directly and shows up in editor previews |
| 2026-10-29 | Rendering | **Light values converted with the old HDRP exposure baked in** (`s = 1/(1.2·2^EV)`, gameplay EV 0.35, menu EV 4.5): directional lux·s/π, point lumen·s/(4π²), emission nits·s. `WeatherConfig.lightningIntensityLux` → `lightningIntensity` (serialized name kept) | URP has no exposure; this keeps the HDRP balance between lamps, sky and emissives |
| 2026-10-29 | Art | Concrete uses the hand-written **`NoWayOut/Triplanar Lit`** (URP has no triplanar Lit), props use URP Lit with the mask map as Metallic + Occlusion map, decals use the hand-written DBuffer shader **`NoWayOut/Decal`**. The mask map packing (R metallic, G occlusion, A smoothness) stays, so `Pack Mask Map (from ARM)` still applies | Shader Graph can't be authored from code; hand-written shaders keep everything in text and reviewable |
| 2026-10-29 | Rendering | **Sky reflection is a baked cubemap** (`T_SkyReflection_Gameplay`, `Tools → No Way Out → Bake Sky Reflection`) from the gradient skybox, not a realtime probe or Generate Lighting | Deterministic in the editor and in builds, no LightingData, no runtime cost. Realtime probes are off in all tiers and don't render in Edit Mode |
